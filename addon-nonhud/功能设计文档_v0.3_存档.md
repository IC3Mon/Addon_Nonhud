# 功能设计文档：NoN HUD 多场景图片集播放 Addon（NoNHud）

- 模组：NoN HUD Addon（临时名 `NoNHud`）
- 环境：Minecraft **1.21.11（正式版）** + Fabric Loader **0.19.5** + Fabric API（版本待与 Loader/MC 匹配核实）+ **NeedsOfNature 1.5.1**
- 版本：v0.3
- 状态：待评审（v0.3 已并入全部待定点结论，PENDING 待编码）
- 关联旧版：`功能设计文档_v0.2_存档.md`（v0.2 归档保留）

## 1. 需求背景与目标

NeedsOfNature（NoN）提供能量、液体槽、妊娠、多槽动画等系统，但它本身没有在玩家 HUD 上按场景播放"整组剧情图集"的能力（其客户端渲染 API 仅覆盖模型纹理/音效/粒子替换）。本附属模组在 NoN 之上，提供一套**外置目录驱动、多触发源、游戏内可配置**的 HUD 图片集播放系统。

目标：**当 NoN 相关的各触发源（A/V/M 三槽动画、V 槽增减、获取精液瓶、妊娠、性欲能量阶段）满足条件时，在玩家 HUD 上按规则播放指定目录下的图片集；图片、阶段、显示位置、播放效果均可在游戏内配置，并在重启后保留。**

约束与边界（本轮已与作者确认）：

| 决策点 | 结论    |
|--------|---------|
| 图片来源 | **外部文件夹**：玩家可往目录添加自己的图片文件，模组运行时扫描并使用    |
| 目录结构 | `NoNHud/` 分两大类：**`event/`**（动画事件槽 A/V/M/botle）与 **`numeric/`**（数值监听槽 Vfull/Afull/pregnant/fxxkme） |
| A/V/M 语义 | event 槽：三个独立并列槽位（对应三种 injector 角色），各自独立触发，与玩家性别无关 |
| 事件槽阶段 | A/V/M 用 **峰前/峰/峰后**（子目录 pre/peak/post），由 `isPeakedStage` + 峰值前后判定 |
| numeric 槽 | Vfull/Afull 按 `up/re × phX`；pregnant 按 progress；fxxkme 按 energy（phX 分档） |
| botle | 获取精液瓶事件触发（**保持单档**，取 `event/botle` 一套图集） |
| 异常图片 | **容忍并装载**：带 `_fYY` 按帧序列播放；不带 `_fYY` 按单张图显示（"就显示这一张"）；仅忽略非 .jpg/.png |
| 同屏规则 | 每个槽位同时最多显示**一张**；event 与 numeric 槽可同屏，位置互不重叠，可配置区域                    |
| 帧播放 | 固定 **fps** 循环（默认 2fps、可配置），切换到新阶段/档位时随机重选 filename    |
| 触发模型 | event 槽靠 NoN 动画事件/注入，numeric 槽靠状态数值监控    |
| 性欲槽 | **= NoN 当前能量 energy**（0–200，分段定阶段）；目录 `numeric/fxxkme`，与模块3**同一件事合一**    |
| 数值槽增减 | **监控穿越阈值**：Vfull/Afull 按 up/re × 分档            |
| 阶段表达 | event 槽用子目录档位（pre/peak/post），numeric 槽用文件名 `phX`    |
| 配置持久化 | 与图片同目录 `NoNHud/config.json`，重启后自动读取    |
| 配置入口 | **游戏内快捷键呼出设置界面**，非手工改文件    |
| 关系 | **完全取代** v0.1 旧设计，旧方案废弃    |

非目标（本轮不做）：不做服务端广播弹图给他人、不做联网图库、不做动态下载图片、不做与女方/其他玩家联动的多人同步弹图（仅看本机玩家自己的状态）。

## 2. 目录结构与图片命名规范（模块 0）

### 2.1 目录树

图片与配置放在模组运行期可写的**外部目录**，典型位于游戏目录下（路径以 Fabric 运行目录为基准，编码阶段定位具体根目录）：

```
NoNHud/
├── config.json                          # 模块4 配置（游戏内写入，重启读取）
│
├── event/                              # 【动画事件槽】——由 NoN 动画事件/注入触发
│   ├── A/                             # A 型 injector 事件
│   │   ├── pre/                       #   峰前（peak 之前）
│   │   │   └── filename_f01.jpg ...
│   │   ├── peak/                      #   峰（isPeakedStage=1）
│   │   └── post/                      #   峰后（peak 收尾）
│   ├── V/                             # V 型 injector 事件（同 pre/peak/post）
│   ├── M/                             # M 型注入事件（同 pre/peak/post）
│   └── botle/                         # 获取精液瓶事件
│
├── numeric/                           # 【数值监听槽】——由玩家状态数值穿越触发
│   ├── Vfull/
│   │   ├── up/                        # V 槽增加
│   │   │   └── filename_ph1_f01.jpg   #   按数值分档 ph1/ph2/ph3…
│   │   └── re/                        # V 槽减少（同样分档）
│   ├── Afull/                         # A 槽（同 up/re + phX 分档）
│   ├── pregnant/                      # 玩家妊娠（按 progress 分档 phX）
│   └── fxxkme/                        # 性欲槽(=energy)（按 energy 分档 phX）
```

### 2.2 文件名规范

两类槽位的文件名语义不同：

**animate 目录（event/ 下）——阶段由子目录表达**
- 文件名只含 `filename_fYY`（帧序号），阶段由所在子目录（`pre`/`peak`/`post`）表达。
- 例：`event/V/pre/filename_f01.jpg` = V 槽在峰前的 filename 第 1 帧。

**numeric 目录（numeric/ 下）——阶段由文件名 phX 表达**
- 文件名含 `filename_phX_fYY`：`phX`=数值分档，`fYY`=帧序号。
- 例：`numeric/Vfull/up/filename_ph1_f01.jpg` = V 槽增加、处于第一档、第 1 帧。

**通用播放语义**：进入某阶段时，先随机选一个文件名（同阶段的所有 `filename` 前缀），然后播该文件名下的整组帧序列（按配置 fps 循环）；切到新阶段时重新随机选文件名并播放。

示例：`event/V/pre` 下同时存在 `filename_f01/02/03` 与 `filename2_f01/02`——进入峰前阶段时等概率随机选 `filename` 或 `filename2`，再循环对应帧。

### 2.3 解析规则（编码约定）

- 目录扫描：仅认 `.jpg` / `.png`。数值槽文件按 `前缀_phN_fM` 解析；动画事件槽文件按 `前缀_fM` 解析（阶段由所在子目录表达）。
- 同一「槽位+阶段」下，同前缀的所有 f 帧构成一个帧序列；多个前缀（filename、filename2…）构成候选，进入该阶段时随机选一个前缀播放。
- **不合规范的兜底（容忍任意图片）**：凡符合 `.jpg`/`.png` 的图片文件**都会被装载**——
  - 若文件名带 `_fYY`（帧标记）：按前缀分组、按帧循环播放（正常帧序列）。
  - 若文件名**不带** `_fYY`（用户随意命名，如 `myimg.jpg`）：作为**单独一张图**显示（单帧、不循环、不自增帧）——即"播放这一张"。
  - 这样用户随手丢进的图片也能显示，只是不会被当作帧序列循环。
- 若某段缺帧或空目录：该段静默不播（不报错）。

## 3. 触发引擎（模块 1/2/3 共用基础）

所有槽位共用一个「状态监控 + 事件监听 → 计算各槽当前 (分类, 槽位, 阶段/档位) → 查图集 → 播放」引擎。

### 3.1 槽位与触发源总表

| 槽位 | 分类 | 阶段来源 | 触发类型 |
|------|------|----------|----------|
| A | event | 峰前/峰/峰后（isPeakedStage 二分） | 事件（A 型注入） |
| V | event | 峰前/峰/峰后（isPeakedStage 二分） | 事件（V 型注入） |
| M | event | 峰前/峰/峰后（isPeakedStage 二分） | 事件（M 型注入/饥饿奖励） |
| botle | event | 单档（`event/botle` 一套图集） | 事件（获取精液瓶） |
| Vfull | numeric | up/re × phX | 数值监控（V 槽穿越阈值） |
| Afull | numeric | up/re × phX | 数值监控（A 槽穿越阈值） |
| pregnant | numeric | phX（progress 分档） | 数值监控（妊娠进度） |
| fxxkme | numeric | phX（energy 分档） | 数值监控（energy） |

### 3.2 同屏与叠加规则

- 每个槽位独立维护"当前显示一张"，槽位之间可同屏，互不覆盖绘制。
- event 槽（A/V/M/botle）与 numeric 槽（Vfull/Afull/pregnant/fxxkme）同时满足时各显示一张，可叠加。
- 总叠加数上限 **<= 配置的槽位数量**，每帧由渲染器按各槽"属于显示或命中的一张"绘制。
- 位置由"显示区域"配置决定（见模块 4），确保互不重叠由玩家配置负责，不做自动防重叠（编码阶段可加默认安全偏移）。

### 3.3 阶段计算（event 槽用峰档，numeric 槽用数值分档）

两种分类的阶段来源不同，不再混用；`phX` 仅用于 numeric 槽，event 槽用语义化的 `pre`/`peak`/`post` 档位。

**event 槽（A/V/M 按峰档判定；botle 单档）**
- **A/V/M** 采用**峰前/峰/峰后**三档，核心依据是 NoN 的 `needsofnature:isPeakedStage()`（`1` 仅当当前动画处于峰值阶段，README 320/533）：
  - **peak 前**（非峰值尚未触发）：取 `pre` 档。由当前 stage 位于峰值 stage 之前判定（峰值 = 第一个未标 `non_peak` 的 stage，README 1591）。
  - **peak**（正在峰值）：取 `peak` 档（`isPeakedStage()=1` 即命中）。
  - **peak 后**（峰值已过、收尾）：取 `post` 档。由当前 stage 位于峰值 stage 之后判定。
- A/V/M **不跟 stage 编号**：它们只关心"在峰前/在峰/在峰后"三态，不区分非峰值内部是第几个 stage。
- 切换：动画推进跨过峰值点时，对应 event 槽从 `pre`→`peak`→`post` 依次切换；动画结束（STOPPED）后 event 槽隐去（无兜底）。
- **botle**：**保持单档**，获取精液瓶事件即播 `event/botle` 一套图集，不分档；动画结束/事件消费后隐去。

**numeric 槽（Vfull/Afull/pregnant/fxxkme）：按数值分档**
- **Vfull/Afull**：先按增减方向选 `up`/`re` 子目录，再按对应槽容量所在档选 `phX`（阈值可配置，如 100→60→30→0）。
- **pregnant**：按 `pregnancy_progress`（0–255）映射 `phX`（档位数可配置）。
- **fxxkme**：按 `energy`（0–200）映射 `phX`（档位边界可配置）。
- numeric 槽全程靠数值穿越触发，不依赖是否有动画在播；数值变化穿档即切换 phX。

### 3.4 injector 角色与 peak 机制（A/V/M 增减的真实来源）

`event/A`、`event/V`、`event/M` 三个目录对应 NoN 的**三种 injector 角色**。README 1402-1412：

| 角色值 | 峰值/动画期间的增减行为 |
|--------|--------------------------|
| `V` | 加 V 型液体槽；peak 阶段把液体增益排成**多个脉冲**跨峰值发放，非一次给满 |
| `A` | 加 A 型液体槽（同样按脉冲） |
| `M` | **不加液体**，峰值时触发迟滞**饥饿奖励**行为 |

- **何时算"触发"**：动画里对应 actor 声明了 `injector` 角色（`injector: true`→V，或显式 `"V"/"A"/"M"`）。未声明则该槽无注入，不触发对应 HUD 槽。
- **强约束**：同一 actor 不能同时是 injector 与 receiver（README 1414），冲突时角色集歧义，按不支持处理。
- **peak 与增减的关系**：peak 阶段只改变 V/A 液体增益的**发放时点（脉冲化）**；M 则是触发饥饿奖励。**增减的幅度/来源**仍是该动画 `liquid_gain_multiplier`（README 1307）与 `NonEvents` hook（README 3104 的 `MODIFY_LIQUID_GAIN`）。"V槽减少"是另一条 tank 变化路径，与 peak 脉冲无关。
- **对模组的意义**：A/V/M 槽的**触发依据是该动画期间对应的 injector 事件/增益**（监听 `NonEvents` 的注入与 liquid gain），阶段仍走 §3.3 event 槽的峰前/峰/峰后档位。

## 4. 各模块明细

### 4.1 模块 1：A/V/M 阶段图集 + Vfull/Afull 数值槽 + 精液瓶

**event 槽（动画事件驱动）：**
- **A/V/M 阶段播放**：监听对应 **injector 角色的注入事件**（A 型/V 型/M 型注入及 liquid gain，见 §3.4）。当动画期间发生对应注入/增益时，进入该槽对应档（`pre`/`peak`/`post`，见 §3.3）图集，按 fps 循环帧序列；峰档切换（`pre`→`peak`→`post`）→ 重选 filename。
- **获取精液瓶**（`event/botle`，单档）：监听 NoN 获取精液瓶对象/事件，触发 `event/botle` 一套图集。

**numeric 槽（数值监听驱动）：**
- **Vfull**：独立监控 `liquid_tank_fill`（不依赖是否有动画）。按增减方向选 `up`/`re`，再按穿越档位选 `phX`。`re` 应对应"V槽降低穿阈值"（如 100→60→30→0）。
- **Afull**：与 Vfull 同理，监控 A 型液体槽。

### 4.2 模块 2：妊娠图集（numeric 槽）

- numeric 槽。玩家处于妊娠（`NonPregnancySnapshot` 非空）时，进入 `numeric/pregnant` 目录。
- 阶段按 `pregnancy_progress`（0–255）映射 ph1/ph2/…。
- 阶段切换、开始时换算并播放；妊娠结束（progress 到顶/清除）→ 停止并隐去。

### 4.3 模块 3：性欲槽（=energy）阶段图集（numeric 槽）

- numeric 槽。**图集目录为 `fxxkme`**（`numeric/fxxkme`，即性欲槽，与模块3同一件事合一）。
- 持续监控 `energy`（0–200），按配置分段映射 ph1/ph2/…。
- energy 升高穿阈值 → 播对应阶段图集（可叠加在当前 event 槽图之上，占用独立显示位）。
- energy 归零/低于阶段 → 适时停止或回落前一阶段图（停顿策略待定点 4）。

### 4.4 模块 4：游戏内配置

**入口**：按下快捷键呼出设置界面（快捷键可在界面内修改绑定）。

**持久化**：所有设置写入与图片同目录的 `NoNHud/config.json`，重启后自动读取并应用。

**可配置项一览**：

| 分类 | 可配置内容 |
|------|------------|
| 图片选择 | 每个槽位/每阶段哪套图集（可指向默认目录或玩家自选目录/文件名）- 待定点 2 |
| 显示区域 | 每个槽位在屏幕上的显示区域框（如 V 屏幕上部分、M 屏幕中间、其他位置），可拖动/数值设置 |
| 移动方式 | 每个槽位：`固定显示` / `方向(上下左右)+距离范围(2-10像素)` / `随机(当前位置为圆心随机方向移动)` |
| 播放方式 | 全局 fps（默认 2）、阶段切换重选策略 |
| 显示效果 | 淡入淡出（时长/曲线）、缩放 / 拉伸显示（等比例 vs 拉伸填满，独立开关）       |
| 阶段阈值 | 各槽分段边界（energy、V槽、妊娠 progress 的档位划分） |

> 配置项极多且带层级，具体交互与数据结构在编码设计时细化；本文档先锁定分类与能力边界。

## 5. 渲染管线（客户端）

- 采用 Fabric `HudRenderCallback` + `DrawContext` 绘制，不走 NoN 客户端渲染 API（低风险面）。
- 每个"已激活槽位"生成一个渲染实例：持有当前 (slot, stage, 当前帧纹理, 显示区域, 移动方式, 透明度)。
- 每帧：更新帧推进（按 fps）、移动位置、透明度→绘制对应一张纹理。
- 支持同时多槽绘制；区域互不重叠依赖配置。
- 帧推进与切换阶段重选在每帧定时器驱动（tick 或帧回调，具体实现阶段定）。

## 8. 待定点结论（v0.3 已全部确认）

- **待定点 1（已定）**：A/V/M 触发=对应 **injector 角色注入事件**（见 §3.4）；阶段=event 槽峰档（§3.3）。无遗留。
- **待定点 2（已定）**：模块4"自行选择图片"的粒度为**选到目录/阶段**——玩家选择"某槽某档位用哪套图集"，不涉及具体文件名。
- **待定点 3（已定）**：`botle` **保持单档**——获取精液瓶事件即播 `event/botle` 一套图集，不分档。

## 10. 打包与首次启动初始化（v0.3 新增需求）

### 10.1 目标

把默认的 `NoNHud` 图片资源**打包进 mod jar**；玩家安装 mod 后**首次启动**时，自动将资源释放到游戏目录，供玩家浏览/增删。

### 10.2 已确认决策

| 决策点 | 结论 |
|--------|------|
| 解压目标 | **与 `mods` 目录同级**（游戏实例根目录；对玩家即 `config/`、`mods/` 的上一级），最终 `NoNHud/` 出现在该处 |
| 覆盖策略 | **仅补缺，不覆盖**——只复制 jar 里目标尚不存在的子目录/文件；玩家已放置的文件一律保留，不覆盖玩家内容 |
| 触发时机 | mod 首次启动（`ModInitializer` 初始化阶段） |

### 10.3 打包结构（jar 内默认资源位置）

- jar 内默认资源按与外部完全一致的树结构存放，例如 `assets/<modid>/default/NoNHud/...`（具体包路径编码阶段确认），首次启动时整体"仅补缺"复制到目标。
- 默认资源本质上就是 §2.1 目录树的样例版（事件槽 event 的 pre/peak/post、数值槽 numeric 的 up/re/pregnant/fxxkme + config.json）。

### 10.4 实现要点（编码阶段细化）

- 用 `FabricLoader.getInstance().getGameDir()` 定位实例根；目标 = gameDir / `NoNHud`。
- 首次启动判断：目标目录不存在则全量补缺；已存在则仅补缺失项。**不覆盖已存在文件**。
- 目标目录里的 `config.json`：若不存在则写入默认；若存在则保留玩家配置（由读取端读取，不覆盖）。
- 该写入动作只由服务端/入口类执行一次；客户端运行目录与实例根一致，避免重复写入。
