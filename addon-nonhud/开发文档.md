## 1. 工程概述

一个 Fabric 客户端侧主导、服务端仅采集 NoN 状态/事件的附属模组。核心机制：

1. **外部目录驱动**：运行时扫描游戏目录下的 `NoNHud/`，按目录结构 + 文件名规范解析出各槽位的图集帧序列索引。
2. **多触发源**：event 槽（A/V/M/botle）靠 NoN 动画/注入事件；numeric 槽（Vfull/Afull/pregnant/fxxkme）靠本机状态数值穿档。
3. **每槽独立渲染**：`HudRenderCallback` 自绘（不走 NoN 客户端渲染 API，降低依赖面），每槽一张，可同屏。
4. **配置持久化**：`NoNHud/config.json` 保存全部设置，游戏内快捷键呼出界面修改，重启后读取。

**线程模型**：扫描器与索引在启动/进世界时构建（O1 缓存，低频率刷新）；数值监控在服务端 tick 采集；渲染在主渲染线程读取索引 + 状态。索引为只读共享数据，靠"重建后引用替换"避免并发写。

## 3. 模块划分与核心类职责

### 3.1 模块 0 目录扫描与索引

| 类 | 职责 |
|----|------|
| `DirectoryScanner` | 递归扫描 `NoNHud/`，识别 event/numeric 两级目录；仅认 `.jpg/.png`；解析时间戳变化供 O1 增量刷新 |
| `FrameSequence` | 一组同前缀帧（`前缀_fYY`）；封装帧列表、当前帧索引、fps 推进；支持"单张图"模式（不带 `_fYY` 时固定一帧） |
| `SlotIndex` | 每槽的索引缓存：`槽位 → 阶段档位(或 up/re/phX) → List<FrameSequence>` |

**解析规则（对应设计 §2.3）**：
- event 槽目录：`event/A/{female,male}/{pre,peak,post}`、`event/V/{pre,peak,post}`、`event/M/…`、`event/botle/`。
- numeric 槽：`numeric/Vfull/{up,re}/`、`numeric/Afull/…`、`numeric/pregnant/`(+`birth/`)、`numeric/fxxkme/`，文件名 `前缀_phX_fYY`。
- 打破文件名的兜底：匹配 `.jpg/.png` 即装载；带 `_fYY` 按帧序列，否则单帧显示。

### 3.2 触发引擎

| 类 | 职责 |
|----|------|
| `TriggerEngine` | 组合事件 + 数值，计算每槽当前 `(分类, 槽位, 阶段档位)`，并驱动 `SlotRenderer` |
| `EventSlotListener` | 注册 NoN 动画/注入事件，更新 A/V/M/botle/pregnant(birth cue) 槽的激活状态与峰档 |
| `NumericMonitor` | 服务端 tick 采样本机 energy/liquid_tank/pregnancy_progress，穿越阈值时更新 numeric 槽档位 |

### 3.3 渲染

| 类 | 职责 |
|----|------|
| `HudRenderer` | 注册 `HudRenderCallback`；每帧按 Z 序（O2）遍历激活槽，把每槽渲染委托给 `SlotRenderer`；实现全局暂停门控（N1） |
| `SlotRenderer` | 单槽渲染实例：持有 (slot, stage, 当前帧逻辑, region, moveMode, alpha)；按 fps 推进帧、淡入淡出、缩放/拉伸、移动 |
| `TextureCache` | 只加载当前阶段需要的帧，切离即释放；缩放结果缓存复用（O2） |

### 3.4 配置

| 类 | 职责 |
|----|------|
| `Config` | 顶层配置模型（§6），含 O4 `slotsEnabled`、N1 `pauseKey`、N2 `zOrder`、O1 `cache.refreshInterval` |
| `ConfigCodec` | `config.json` 读写；缺失字段用默认值；热重载（O3）时重建索引 |

## 4. 数据与控制流

**启动**：
1. `NoNHudAddon.onInitialize`：定位 `gameDir/NoNHud`（`FabricLoader.getInstance().getGameDir()`）；§10 首次启动"仅补缺"解压内置默认资源；初始化配置。
2. `NoNHudClient.onInitializeClient`：注册 HUD 回调、扫描器建索引、绑定快捷键。

**运行**：
```
[NoN 事件/injector 注入] ──→ EventSlotListener ──→ (A/V/M/botle, 峰档)
[本机数值 tick 采样]      ──→ NumericMonitor  ──→ (Vfull/Afull/pregnant/fxxkme, up/re/phX, progress/energy/biirth)
                                            │
                                    TriggerEngine ──→ SlotRenderer 状态
                                            │
     每帧: HudRenderCallback ──→ 全局暂停门控(N1) ──→ 按 Z 序(O2) 绘制各槽
```

**A 槽性别强判**（设计 §3.3）：injector=A → `A/{receiver性别}`；receiver 男 + injector=V → 强制 `A/male`。此判定在 `EventSlotListener` 中完成，仅影响目录选择，不影响峰档。

## 5. 接口假设与待核清单

以下来自设计 §7，编码前必须用真实 jar 复核（命令见 CHECKLIST.md）：

| # | 待核项 | 需要的确切签名 |
|---|--------|----------------|
| 1 | 监听 A/V/M injector 注入/liquid gain | `NonEvents` 的注入 hook / `MODIFY_LIQUID_GAIN` context |
| 2 | 读取当前动画的 injector 角色 | `NonAnimationApi` 定义视图的 actor/injector 访问器 |
| 3 | 读取玩家 energy / liquid_tank_fill / A 槽 / pregnancy_progress | `NonPlayerApi` 状态快照访问器 |
| 4 | Vfull/Afull 增减/穿越阈值取数 | 状态快照数值字段 |
| 5 | 获取精液瓶时机 | 事件/回调类型 |
| 6 | 妊娠开始/结束/进度 | `NonPregnancySnapshot` 字段 + 事件 |
| 7 | event 槽峰档（peak 前后） | `isPeakedStage` + stage 与峰值比较 |

`Client` 侧不直接依赖 NoN 客户端类，因此若 NoN 服务端 API 足以取到本机状态，可省掉自定义网络包；否则补 `AnimationSyncPacket`。

**核对结果（已用 needsofnature-1.5.1+1.21.11.jar javap 复核，详情见 CHECKLIST.md §2）**：
- #1 `NonEvents.MODIFY_LIQUID_GAIN` ✅；另有 `LIQUID_TANK_CHANGED` / `PREGNANCY_CHANGED` / `PLAYER_GENDER_CHANGED` 等。
- #2 无 actor 视图 API；用 `NonAnimationDefinition.actors()`（`NonAnimationActor.label()/activity()`）读角色。
- #3 `NonPlayerApi.getState(player)` → `NonPlayerStateSnapshot(gender, liquidTank, mess, destroyedSkin, pregnancy, accessoryEffects)`；⚠️ **无 energy**，能量需单独取数（`NonEnergySnapshot` 存在但快照不含，可能走 NonEntityApi）。
- #4 液体：`NonLiquidTankSnapshot(storedMl, capacityMl, fillRatio, ...)`；能量无现成字段。
- #5 精液瓶无独立回调，用动画 `STAGE_CHANGED` 时机捕获。
- #6 `NonPregnancySnapshot(entityTypeId, endTick, pendingHatch)`+`active()`；**无进度百分比**，用 `endTick - world.getTime()` 反推。
- #7 无 `isPeakedStage`；峰档自算：stage 序号与 `stages().size()-1`（末段）比较。
- 动画事件：`com.nonid.api.animation.NonAnimationEvents` 的 `STARTED/STAGE_CHANGED/STOPPED` 均已实现服务端监听 + S2C 下发（见 `server/NoNAnimationListener.java`），客户端 HUD 已能收到 `(动画ID, stage序号)`。

## 7. 打包与首次启动解压

- jar 内置默认资源：`assets/<modid>/default/NoNHud/...`（树结构与外部一致，即 §11.1 的示例目录）。
- 首次启动（`NoNHudAddon.onInitialize`）"仅补缺"复制到 `gameDir/NoNHud/`：
  - 不覆盖已存在文件（保留玩家内容）。
  - `config.json` 缺失才写入默认，存在则保留。
- 用 `FabricLoader.getInstance().getGameDir()` 定位；与服务端/入口一致，避免重复写入。

## 9. 关键风险与规避

| 风险 | 规避 |
|------|------|
| NoN 服务端 API 签名与 README 推断不符 | §5 复核先行；`compileOnly` 隔离，运行期以 mods 为准 |
| 1.21.11 与 Loom/API 版本不匹配导致构建失败 | 确认 Loom/yarn/fabric-api 版本与 MC 1.21.11 匹配后再动手 |
| 外部图片尺寸过大导致显存压力 | O2 只加载当前帧 + 缩放缓存复用 |
| 多槽同屏重叠 | 玩家按 region 配置自负责；可加默认安全偏移 |
| 首次解压覆盖玩家内容 | §10"仅补缺"策略，不覆盖既有文件 |
